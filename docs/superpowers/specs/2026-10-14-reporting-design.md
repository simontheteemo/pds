# PDS Reporting Export (v1) — Design Spec

- Date: 2026-10-14
- Author: @simon (with Claude)
- Status: **Proceeding on the user's "keep going, verify later" instruction.** Every decision below was made by Claude and is open to review.
- Builds on: [Foundation spec](2026-09-29-foundation-design.md) (§3.3 module rules, §10 item 4 "Reporting without SQL", §11 roadmap item 6) · architecture set (`docs/architecture/pds-architecture.html`: "Reports are pre-computed or run on an S3 export with Athena")

## 1. Purpose

Get data out of PDS for reporting and analysis beyond the in-app running totals. Today each module shows its data per project on screen. A manager who wants to:
- compare risk profiles across projects
- pivot cost lines across the portfolio
- track settlements by month
- hand a lender a consent-condition list

has to copy it out of screens by hand.

v1 adds a **Reports** page with one CSV download per dataset. Each download covers the **whole portfolio** (every project, including archived ones) and opens directly in Excel. Every dataset is defined by the module that owns the data, through a small export contract, so the same datasets can later feed a scheduled S3/Athena export without being redesigned.

### Stated vs decided

| Stated by @simon / the brief | Decided by Claude (review later) |
|---|---|
| "No ad-hoc SQL. Reports are pre-computed or run on an S3 export with Athena"; "the Athena export in the reporting sub-project" | **v1 is Option A**: on-demand CSV downloads generated by the API. **Option B** (scheduled S3 export + Glue + Athena) is **deferred** but designed for: the same dataset contract feeds it unchanged (§7) |
| Pick the smallest genuinely useful v1 | 8 portfolio-wide datasets: `projects`, `risks`, `contracts`, `cost-lines`, `cost-entries`, `consents`, `consent-conditions`, `units`. Not in v1: a contractor directory export, per-project exports (the in-app screens already cover one project), XLSX, filters, and a portfolio "summary" sheet |
| Respect module rules: read through Contracts, or each module exports its own data | **Each module exports its own data.** A new `PDS.Reporting` module publishes `IExportDataset` in its `Contracts`. Each data module implements it internally against its own table and registers it in DI. Reporting enumerates the registrations and never references a data module. No new query interfaces are added to any other module's `Contracts` |
| Raw DynamoDB exports would bypass module boundaries | Rejected. They export the storage shape (`pk`/`sk`, DynamoDB JSON, omitted attributes), bypass the computed figures (cost FFC/variance, risk score/band, due state), and couple consumers to every table's internals |
| Exports likely contain commercial data; decide which roles may export | New policy **`CanExport` = Manager or Admin**, owned and registered by the Reporting module. Viewers can still see the same data screen by screen, but they can't bulk-download it. Every export is logged (user, dataset, row count) |
| Lightweight, AWS-managed, < US$10/mo | No new infrastructure and no new packages. CSV is written by a small in-house writer (RFC 4180). Run cost is a few Lambda invocations plus a scan of each table per download |
| CSV or XLSX | **CSV only.** XLSX would need a package (ClosedXML or MiniExcel), and CSV with a UTF-8 BOM opens in Excel with correct characters. It's also the format Athena reads |
| — | Column names are `snake_case` and dataset names are `kebab-case`, both treated as a stable public contract (BI tools, Athena tables later). Values use invariant formats: ISO dates `yyyy-MM-dd`, UTC timestamps `yyyy-MM-ddTHH:mm:ssZ`, decimals with `.` and no thousands separator, `true`/`false`, and enum names as stored |
| — | Every child dataset carries `project_id`, `project_code` and `project_name`, looked up via `IPortfolioQueries.GetSummaries`, so a single sheet can be filtered by project without a join. A row whose project can't be found keeps its `project_id`, with blank code and name |
| — | Amounts are exported as plain decimals, with a `currency` column (the deployment currency from `LocaleOptions`, or the stored money currency where the row has one). Cost amounts exclude GST, matching the cost report |
| — | Buyer **email and phone are not exported** (personal data that reporting doesn't need). Buyer name and solicitor are exported, because settlement reporting needs them |
| — | Spreadsheet formula-injection guard: a **text** value starting with `=`, `+`, `-`, `@`, tab or CR is prefixed with `'`. Numbers are never altered |
| — | Datasets and the catalog are scoped DI services (IPortfolioQueries is scoped); a bad dataset name surfaces on the first export request |
| No new tests (standing directive) | Verify by build, type-check, lint, synth, and manual API checks against DynamoDB Local |

### Success criteria
- A Manager opens **Reports**, sees the eight datasets with a one-line description each, clicks **Download CSV** on any of them, and gets `pds-<dataset>-<yyyy-MM-dd>.csv`. The file opens in Excel with correct characters (e.g. macrons in "Tāmaki") and one row per entity across all projects.
- A Viewer opening Reports sees a short "Exports are available to Managers and Admins" message, and the API returns 403 for them on every export endpoint.
- `PDS.Reporting` references only `PDS.Shared`. Each data module references `PDS.Reporting` for its `Contracts` only. No module reads another module's table.
- No changes to infra, `PDS.Shared` or `web/src/shared` (other than the generated API files).

## 2. Architecture

```
PDS.Reporting  (new module, no tables)
├── Contracts/  IExportDataset, ExportTable, ExportColumn<T>        ← public
├── ReportingModule.cs   AddReportingModule(), MapReportingEndpoints(), ReportingPolicies.CanExport
└── internal: ExportCatalog (enumerates IEnumerable<IExportDataset>), CsvWriter, endpoints

PDS.Portfolio / Risks / Contractors / Costs / Consents / Sales
└── Features/Export*.cs  internal sealed class …ExportDataset : IExportDataset   (reads its own store)
    registered in Add<Module>Module(): services.AddScoped<IExportDataset, …>()
```

- **Dependency direction:** data module → `PDS.Reporting.Contracts`. Reporting never references a data module, so it can't read another module's table, and later modules (Documents, Cashflow) add a dataset by registering one class.
- **Contract (public, in `PDS.Reporting.Contracts`):**

```csharp
public interface IExportDataset
{
    /// <summary>Stable kebab-case id: URL segment, file name and (later) S3 prefix / Athena table.</summary>
    string Name { get; }
    string Title { get; }
    string Description { get; }
    Task<ExportTable> LoadAsync(CancellationToken ct);
}

public sealed record ExportColumn<T>(string Name, Func<T, object?> Value);

public sealed class ExportTable
{
    public IReadOnlyList<string> Columns { get; }
    public IReadOnlyList<object?[]> Rows { get; }
    public static ExportTable From<T>(IEnumerable<T> rows, IReadOnlyList<ExportColumn<T>> columns);
}
```

- `ExportCatalog` (scoped, built per request from `IEnumerable<IExportDataset>`) checks when it is first built (the first `/api/reporting` request, not at startup) that every name matches `^[a-z][a-z0-9-]*$` and is unique, and throws otherwise. It lists datasets ordered by `Title`.
- `CsvWriter` (internal, static) turns an `ExportTable` into UTF-8 bytes with a BOM. It uses a header row and CRLF line endings, and quotes a field when it contains `,`, `"`, CR or LF (doubling inner quotes). It formats values by type:
  - `null` → empty
  - `string` → injection guard, then quote if needed
  - `bool` → `true`/`false`
  - `DateOnly` → `yyyy-MM-dd`
  - `DateTimeOffset` → UTC `yyyy-MM-ddTHH:mm:ssZ`
  - `Enum` → name
  - `IFormattable` (numbers, `Guid`) → `ToString(null, InvariantCulture)`
  - anything else → `ToString()` treated as text
- Each module's dataset shares one helper pattern: load the module's rows, collect distinct `ProjectId`s, call `IPortfolioQueries.GetSummaries`, then order by `project_code` and the module's natural order. Portfolio's own dataset uses `ProjectStore.ListAllAsync`.

## 3. Datasets

Grain is one row per entity. All datasets include archived projects. Columns are listed in output order.

| Name (module) | Title | Grain | Columns |
|---|---|---|---|
| `projects` (Portfolio) | Projects | project | `project_id, project_code, project_name, stage, status, archived, address_line, suburb, city, region, postcode, legal_description, title_reference, land_area_sqm, planned_start, planned_completion, actual_start, actual_completion, budget_amount, currency, project_manager, description, created_at, updated_at` |
| `risks` (Risks) | Risks | risk | `risk_id, project_id, project_code, project_name, title, category, likelihood, impact, score, band, status, owner, due_date, description, mitigation, closing_note, closed_at, created_at, updated_at` |
| `contracts` (Contractors) | Contracts | contract | `contract_id, project_id, project_code, project_name, contractor_id, contractor_name, title, reference, form, status, value_amount, currency, start_date, end_date, retention_percent, notes, created_at, updated_at` |
| `cost-lines` (Costs) | Cost report lines | budget line | `budget_line_id, project_id, project_code, project_name, line_name, sort_order, budget, committed, actual, forecast_remaining, forecast_final_cost, forecast_to_complete, variance, currency, notes` (`forecast_remaining` is the entered value, blank when computed; the other figures come from `CostCalculator`, same as the cost report) |
| `cost-entries` (Costs) | Commitments and actuals | commitment or actual | `entry_id, entry_kind (Commitment\|Actual), project_id, project_code, project_name, budget_line_id, budget_line_name, type, contract_id, contract_title, contractor_name, payee, description, reference, date, amount, currency, notes, created_at` (line name `(deleted line)` and contract title `(unknown contract)` as in the cost report; contract names via the existing `IContractQueries.GetProjectContracts` per project) |
| `consents` (Consents) | Consents | consent | `consent_id, project_id, project_code, project_name, type, title, authority, reference, status, lodged_date, granted_date, expiry_date, condition_count, open_condition_count, notes, created_at, updated_at` |
| `consent-conditions` (Consents) | Consent conditions | condition | `condition_id, consent_id, project_id, project_code, project_name, consent_type, consent_title, consent_reference, consent_status, reference, description, due_date, completed_on, due_state, created_at, updated_at` (`due_state` is computed as of the deployment's local today with the same rule as the due list) |
| `units` (Sales) | Units and sales | unit | `unit_id, project_id, project_code, project_name, identifier, type, bedrooms, bathrooms, car_parks, floor_area_sqm, land_area_sqm, list_price, sale_status, buyer_name, buyer_solicitor, agreement_date, sale_price, deposit, unconditional_date, settlement_date, currency, notes, created_at, updated_at` |

Row order:
- `projects`: by code
- `risks`: by project code, then score desc, then title
- `contracts`: by project code, then contractor name, then title
- `cost-lines`: by project code, then sort order, then name
- `cost-entries`: by project code, then date, then kind
- `consents`: by project code, then title
- `consent-conditions`: by project code, consent title, due date (nulls last), then reference
- `units`: by project code, then the module's natural identifier order

Data access stays inside each module:
- Portfolio uses `ProjectStore.ListAllAsync`.
- Sales uses `UnitStore.ListAllAsync`.
- Consents uses `ConsentStore.ScanAllAsync`.
- Risks, Contractors (contracts) and Costs each gain an internal `ScanAllAsync` on their store. It's a paged, consistent `Scan` filtered by sort-key prefix.

These scans are full-table reads of single-tenant tables (expected to be hundreds to low thousands of items), which ADR-0002 accepts. The cost of a download is negligible at on-demand PAY_PER_REQUEST pricing.

## 4. API

Base path `/api/reporting/exports`. The whole group requires `CanExport`.

| Method | Route | Behaviour |
|---|---|---|
| GET | `` | `200 ExportDatasetInfo[]` (`{ name, title, description }`), ordered by title. Operation `ListExports` |
| GET | `/{name}` | `200 text/csv; charset=utf-8`, `Content-Disposition: attachment; filename="pds-<name>-<yyyy-MM-dd>.csv"` (local date per `LocaleOptions`) and `Cache-Control: no-store`. Unknown name → `404`. Operation `DownloadExport` |

- **Logging:** each download logs `Information` with `Dataset`, `Rows` and `UserName` (via `ICurrentUser`). That gives an audit trail of who took which data.
- **Policy:** `ReportingPolicies.CanExport = "CanExport"` is registered in `AddReportingModule()` with `services.AddAuthorizationBuilder().AddPolicy(...)` = `RequireRole(Roles.Manager, Roles.Admin)`. That keeps `PDS.Shared` and `PDS.Api/Security` untouched.
- **Size:** responses are buffered. Lambda's 6 MB response limit caps a dataset at roughly 15–20k rows, far above v1 volumes (see §8).

## 5. Frontend

- A new feature folder, `web/src/features/reporting`:
  - `api.ts` for `useExports()` (the catalog) and `downloadExport(api, name)`. The download uses openapi-fetch with `parseAs: 'blob'`, builds an object URL and clicks a temporary `<a download>`. The file name is computed client-side as `pds-<name>-<today>.csv`, so no CORS header exposure is needed.
  - `ReportsPage.tsx`
- **Reports page** (`/reports`):
  - Header: title "Reports" and a note that the files are CSV downloads covering every project (including archived ones), that they open in Excel, and that amounts are in the deployment currency and exclude GST.
  - A table with one row per dataset: title, description and a **Download CSV** button. The button shows a loading state while its download runs. A failure shows a red notification with the problem title.
  - **Viewers**: when `/api/me` roles include neither Manager nor Admin, the page shows an info Alert "Exports are available to Managers and Admins." and doesn't fetch the catalog. Roles are read via `useMe()`, so `web/src/shared` doesn't change.
- **Wiring:** one route in `routes.tsx` and one `NavLink` "Reports" in `AppLayout.tsx` (shown to everyone; the page handles Viewers).

## 6. Error handling

| Case | Result |
|---|---|
| Unknown dataset name | 404 ProblemDetails |
| Viewer / no group | 403 (policy); the UI doesn't call the API for Viewers |
| A dataset throws (e.g. DynamoDB error) | 500 ProblemDetails with a `correlationId`; the UI shows the notification |
| Duplicate or invalid dataset name registered | Every `/api/reporting/*` request fails with 500 (`ExportCatalog` constructor throws when first built) |

## 7. Deferred: Option B (scheduled S3 export + Athena)

When the client picks a BI tool, or the data outgrows Excel, the next step is:
1. An EventBridge Scheduler rule (daily) invokes the **existing API Lambda** or a small sibling Lambda from the same assembly. It enumerates the same `IExportDataset` registry and writes `s3://<deployment>-exports/<name>/dt=<yyyy-MM-dd>/<name>.csv`.
2. A Glue database, with one table per dataset (OpenCSVSerDe, `skip.header.line.count=1`, partition projection on `dt`), and an Athena workgroup with a per-query bytes-scanned limit and its own results bucket with a lifecycle rule.

The CSV formula-injection guard (`'` prefix) is for spreadsheet consumers; the S3/Athena writer should skip it so Athena sees the raw values.

This costs cents per month at these volumes. Nothing in v1 needs to change: dataset names become S3 prefixes and table names, and column names are already `snake_case` and type-stable.

It was deferred because:
- no BI tool is identified yet
- the data volume is small enough for Excel
- it adds four AWS resources and an operational schedule for no current consumer

## 8. Risks and open items

| # | Risk | Mitigation / trigger |
|---|---|---|
| 1 | A dataset exceeds Lambda's 6 MB response limit (≈ 15–20k rows; the Lambda payload JSON-escapes text bodies, so the effective limit is somewhat below 6 MB) | Not expected for a single tenant. If it happens, the download fails with a 500. The fix is Option B, or writing to S3 and returning a presigned URL |
| 2 | Full-table scans on each download | Acceptable at these volumes (ADR-0002). Only Managers and Admins can trigger them. Revisit with Option B if usage grows |
| 3 | Column names are a public contract once BI tools consume them | Treat renames as breaking; add columns only at the end |
| 4 | Viewers might legitimately need exports (e.g. a lender's QS) | One-line change to the `CanExport` policy |
| 5 | Sibling branches (Documents, Cashflow) won't contribute datasets until they register an `IExportDataset` | Follow-up for those modules; no change to Reporting needed |
