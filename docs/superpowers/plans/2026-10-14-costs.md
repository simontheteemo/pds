# PDS Cost Tracking (v1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Prerequisite:** the Contractors module (`docs/superpowers/plans/2026-09-30-contractors.md`) must be merged into `main`, and this branch rebased onto it, before Task 1 starts. Task 1 extends `PDS.Contractors`.

**Goal:** A per-project cost report: budget lines, commitments and actuals (optionally linked to contracts), with budget, committed, actual, forecast-final, forecast-to-complete and variance totals computed per line and per project.

**Architecture:** A new module `src/Modules/PDS.Costs` owns the `costs` table. Its public Contracts are `BudgetLineId`, `CommitmentId` and `ActualCostId`; everything else is internal. All of a project's items share `pk = PROJECT#<id>` and are told apart by sk prefix (`LINE#`, `COMMIT#`, `ACTUAL#`). There is no GSI. Totals are computed on read from one Query. The module reads projects through `PDS.Portfolio.Contracts` and contracts through a **new** `PDS.Contractors.Contracts.IContractQueries`, which Task 1 adds. The web app adds `web/src/features/costs`: a cost report page at `/projects/:id/costs` and a `ProjectCostsCard` on the project detail page.

**Tech Stack:** Same as the foundation, Risks and Contractors. No new packages.

**Spec:** `docs/superpowers/specs/2026-10-14-costs-design.md`. Reference implementations to mirror:
- `src/Modules/PDS.Risks`: per-project partition, store, endpoints, problems.
- `src/Modules/PDS.Contractors`: Money fields on `Contract`, `ContractStore`, `ProjectLookup`.
- `web/src/features/risks` and `web/src/features/contractors`: section, modal and mutation-error helper.

## Global Constraints

- All foundation constraints apply:
  - net10.0 and central package versions.
  - Only `Contracts/` and `CostsModule` are public.
  - `pk`/`sk` string keys.
  - ProblemDetails errors; camelCase JSON with string enums (`allowIntegerValues: false`).
- **No new tests** (user directive). Verify with:
  - `dotnet format PDS.slnx`, then `dotnet build PDS.slnx` (0 warnings). Existing tests must still compile.
  - In web/: `npm run gen:api && npm run typecheck && npm run lint && npm run build`.
  - In infra/: `npx aws-cdk@2.1143.0 synth -c deployment=example-dev`.
  - The manual checks each task names. Run the API with `--urls http://localhost:5082` and Vite with `--port 5192`. Reuse DynamoDB Local on :8000 if it's already running; never stop it.
- Query parameters are plain handler parameters (not `[AsParameters]`).
- All amounts are `Money` in `LocaleOptions.Currency`, at most 2 dp, with |amount| ≤ 999,999,999.99. They're stored as `<name>Amount` (N) and `currency` (S). They exclude GST.
- Sign rules:
  - Budget and ForecastRemaining ≥ 0.
  - Commitment amount ≥ 0 unless the type is `Variation`.
  - Actual amount ≠ 0 (negative = credit note).
- Policies:
  - Reads need CanRead.
  - Creating and updating need CanWrite.
  - Every DELETE needs CanAdminister.
- Every write on an archived project returns 400 on `projectId`. An unknown project returns 404 on every route.
- Shared wiring files (`PDS.slnx`, `PDS.Api.csproj`, `Program.cs` (api and infra), `routes.tsx`, `ProjectDetailPage.tsx`) get minimal, additive one-line edits.
- Commit messages are conventional (`feat(costs): …`) and end with the Co-Authored-By trailer your environment specifies.

## Review Focus

1. **Totals arithmetic** (§3.3). Each case below gives Budget, Committed, Actual and the override, then the expected FFC, FTC and Variance:
   - B=100, C=0, A=0 → FFC 100, FTC 100, Var 0.
   - B=100, C=120, A=50 → FFC 120, FTC 70, Var −20.
   - B=100, C=40, A=60 (an uncommitted invoice) → Exposure 60, FFC 100, FTC 40, Var 0.
   - B=100, C=80, A=10, override 5 → FFC 85, FTC 75, Var 15.
   - A negative variation reduces Committed.
   - A credit note reduces Actual.
   - Project totals equal the sum of the line rows.
2. **Cross-project references.** A `budgetLineId` from another project, or a `contractId` belonging to another project (or an unknown one), returns 400 on that field. It never saves and never returns 500.
3. **Deleting a line in use.** DELETE on a line with any commitment or actual returns 400 on `budgetLineId`, and nothing is deleted.
4. **Duplicate line names.** Create or rename to an existing name (case-insensitive, trimmed) returns 400 on `name`. Renaming a line to its own name with different casing is allowed. "Add standard lines" twice adds nothing the second time.
5. **Stale and archived writes.** PUT and DELETE with a stale version return 409. Any write on an archived project returns 400 on `projectId`, while GET still works.

internal sealed class ContractQueries(ContractStore contracts, ContractorStore contractors) : IContractQueries
{
    public async Task<IReadOnlyList<ContractSummary>> GetProjectContracts(ProjectId projectId, CancellationToken ct)
    {
        var list = await contracts.ListForProjectAsync(projectId, ct);
        if (list.Count == 0)
            return [];

                c.Id, c.ProjectId, c.ContractorId,
                names.GetValueOrDefault(c.ContractorId, "(unknown contractor)"),
                c.Fields.Title, c.Fields.Reference, c.Fields.Status.ToString(),
                c.Fields.Value?.Amount, c.Fields.Value?.Currency))
            .ToList();
    }

// Domain/CostFigures.cs
namespace PDS.Costs.Domain;

internal sealed record CostFigures(
    decimal Budget, decimal Committed, decimal Actual,
    decimal ForecastFinalCost, decimal ForecastToComplete, decimal Variance)
{
    public static readonly CostFigures Zero = new(0, 0, 0, 0, 0, 0);

    public CostFigures Plus(CostFigures o) => new(
        Budget + o.Budget, Committed + o.Committed, Actual + o.Actual,
        ForecastFinalCost + o.ForecastFinalCost, ForecastToComplete + o.ForecastToComplete, Variance + o.Variance);
}

// Domain/CostCalculator.cs
namespace PDS.Costs.Domain;

internal static class CostCalculator
{
    public static CostFigures ForLine(decimal budget, decimal? forecastRemaining, decimal committed, decimal actual)
    {
        var exposure = Math.Max(committed, actual);
        var remaining = forecastRemaining ?? Math.Max(budget - exposure, 0m);
        var ffc = exposure + remaining;
        return new CostFigures(budget, committed, actual, ffc, ffc - actual, budget - ffc);
    }

    /// <summary>Per-line figures keyed by line id, and the project total (the sum of the line rows).</summary>
    public static (IReadOnlyDictionary<BudgetLineId, CostFigures> Lines, CostFigures Total) For(
        IReadOnlyList<BudgetLine> lines, IReadOnlyList<Commitment> commitments, IReadOnlyList<ActualCost> actuals)
    {
        var committed = commitments.GroupBy(c => c.Fields.BudgetLineId).ToDictionary(g => g.Key, g => g.Sum(c => c.Fields.Amount.Amount));
        var actual = actuals.GroupBy(a => a.Fields.BudgetLineId).ToDictionary(g => g.Key, g => g.Sum(a => a.Fields.Amount.Amount));
        var perLine = lines.ToDictionary(
            l => l.Id,
            l => ForLine(l.Fields.Budget.Amount, l.Fields.ForecastRemaining?.Amount,
                         committed.GetValueOrDefault(l.Id), actual.GetValueOrDefault(l.Id)));
        var total = perLine.Values.Aggregate(CostFigures.Zero, (sum, f) => sum.Plus(f));
        return (perLine, total);
    }
}
