# PDS Sales Pipeline (v1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A per-project register of saleable units or lots with a sale-status pipeline, buyer and S&P details, a per-project sales summary and a cross-project Sales page.

**Architecture:** A new module `src/Modules/PDS.Sales` (Contracts: `UnitId`; everything else internal) owns the `sales` table. Each unit is one item (`PROJECT#pid` / `UNIT#uid`, all units listed via `gsi1pk = UNIT`) with its current sale embedded. It reads projects only through `PDS.Portfolio.Contracts`. The web app adds `web/src/features/sales`: a Sales card on the project detail page (summary, unit table, unit and sale modals) and a `/sales` page.

**Tech Stack:** Same as the foundation, Risks and Contractors (.NET 10 Minimal APIs, FluentValidation, AWS SDK DynamoDB; React, Mantine 9, TanStack Query, openapi-fetch, Zod 4).

**Spec:** `docs/superpowers/specs/2026-10-14-sales-design.md`. Reference implementations to mirror: `src/Modules/PDS.Risks` (module shape, store, endpoints, problems) and `src/Modules/PDS.Portfolio` (Money in DTOs: `ProjectDtos.ToFields(currency)`, `ProjectItemMapper` budget mapping, `ProjectInputValidator` money rules). On the web side, mirror `web/src/features/risks` (section, modals, error helper) and `web/src/features/portfolio` (`ProjectForm` NumberInput money props, `ProjectsPage` table).

## Review Focus

1. **Status-dependent required fields.** PUT sale with status Conditional and no `salePriceAmount` → 400 on `salePriceAmount`; Settled without `settlementDate` → 400 on `settlementDate`; Reserved without `buyerName` → 400 on `buyerName`. Never a 500 from the domain guard.
2. **Clearing on Available/Withdrawn.** Moving a Settled unit to Available returns the unit with every buyer/sale field null, and the summary no longer counts its sale price in contracted or settled value.
3. **Identifier uniqueness.** Creating "lot 3" when "Lot 3" exists → 400 on `identifier`; renaming a unit to its own identifier (any case) is allowed; renaming to another unit's identifier → 400.
4. **Summary arithmetic.** Withdrawn units are excluded from list value; units without a list price or sale price contribute 0; Reserved sale prices are not contracted; values are decimals in the deployment currency.
5. **Stale edits and archived projects.** Unit update and sale update return 409 on a stale version; POST unit on an archived project → 400 on `projectId`; unknown project → 404; sale updates on an archived project's units still succeed.

`Domain/SaleRules.cs`:
```csharp
namespace PDS.Sales.Domain;

internal static class SaleRules
{
    public const int NameMaxLength = 200;
    public const int EmailMaxLength = 200;
    public const int PhoneMaxLength = 50;

    /// <summary>Available and Withdrawn carry no sale; every other status does.</summary>
    public static bool HasSale(SaleStatus s) => s is not (SaleStatus.Available or SaleStatus.Withdrawn);

    public static bool RequiresBuyer(SaleStatus s) => HasSale(s);

    public static bool RequiresAgreement(SaleStatus s) =>
        s is SaleStatus.Conditional or SaleStatus.Unconditional or SaleStatus.Settled;

    public static bool RequiresUnconditional(SaleStatus s) => s is SaleStatus.Unconditional or SaleStatus.Settled;

    public static bool RequiresSettlement(SaleStatus s) => s is SaleStatus.Settled;

    /// <summary>Contracted = an S&P agreement is signed (Conditional or later, not Withdrawn).</summary>
    public static bool IsContracted(SaleStatus s) => RequiresAgreement(s);

    public static bool IsOrdered(DateOnly? earlier, DateOnly? later) =>
        earlier is null || later is null || later.Value >= earlier.Value;

    public static SaleDetails Normalise(SaleDetails d) => d with
    {
        BuyerName = UnitRules.Clean(d.BuyerName),
        BuyerEmail = UnitRules.Clean(d.BuyerEmail)?.ToLowerInvariant(),
        BuyerPhone = UnitRules.Clean(d.BuyerPhone),
        BuyerSolicitor = UnitRules.Clean(d.BuyerSolicitor),
    };

    public static void EnsureValid(SaleStatus status, SaleDetails d)
    {
        if (RequiresBuyer(status) && d.BuyerName is null)
            throw new ArgumentException("A buyer is required.", nameof(d));
        if (RequiresAgreement(status) && (d.AgreementDate is null || d.SalePrice is null))
            throw new ArgumentException("Agreement date and sale price are required.", nameof(d));
        if (RequiresUnconditional(status) && d.UnconditionalDate is null)
            throw new ArgumentException("Unconditional date is required.", nameof(d));
        if (RequiresSettlement(status) && d.SettlementDate is null)
            throw new ArgumentException("Settlement date is required.", nameof(d));
        if (d.SalePrice is { Amount: < 0 } || d.Deposit is { Amount: < 0 })
            throw new ArgumentException("Amounts cannot be negative.", nameof(d));
        if (d.SalePrice is { } price && d.Deposit is { } deposit && deposit.Amount > price.Amount)
            throw new ArgumentException("Deposit cannot exceed the sale price.", nameof(d));
        if (!IsOrdered(d.AgreementDate, d.UnconditionalDate) || !IsOrdered(d.AgreementDate, d.SettlementDate)
            || !IsOrdered(d.UnconditionalDate, d.SettlementDate))
            throw new ArgumentException("Sale dates are out of order.", nameof(d));
    }
}
```

`Domain/Unit.cs` (mirror `Risk`): private constructor; properties `Id` (UnitId), `ProjectId`, `Fields`, `Status`, `Sale` (SaleDetails?), `Created`, `Updated`, `Version`.
- `static Create(ProjectId, UnitFields, AuditStamp)`: normalise, validate, `Status = Available`, `Sale = null`, version 1.
- `static Rehydrate(...)` with every property.
- `Update(UnitFields, AuditStamp)`: normalise, validate, `EnsureOneCurrency`, touch.
- `UpdateSale(SaleStatus status, SaleDetails? sale, AuditStamp stamp)`:
  - if `!SaleRules.HasSale(status)` → `Sale = null` (the request's sale fields are ignored);
  - otherwise normalise `sale ?? empty`, `SaleRules.EnsureValid(status, normalised)`, `Sale = normalised`;
  - set `Status`, `EnsureOneCurrency`, touch.
- `private void EnsureOneCurrency()`: all non-null of `Fields.ListPrice`, `Sale?.SalePrice`, `Sale?.Deposit` share one `Currency`; throw `InvalidOperationException` otherwise.
- `public string? Currency` → the currency of the first non-null amount (used by the mapper).

`Domain/SalesTotals.cs`:
```csharp
namespace PDS.Sales.Domain;

/// <summary>Counts by status and values for a set of units. Values are amounts in the deployment currency.</summary>
internal sealed record SalesTotals(
    int TotalUnits, int Available, int Reserved, int Conditional, int Unconditional, int Settled, int Withdrawn,
    decimal ListValue, decimal ContractedValue, decimal SettledValue)
{
    public static SalesTotals For(IEnumerable<Unit> units)
    {
        var list = units.ToList();
        int Count(SaleStatus s) => list.Count(u => u.Status == s);
        return new SalesTotals(
            list.Count,
            Count(SaleStatus.Available), Count(SaleStatus.Reserved), Count(SaleStatus.Conditional),
            Count(SaleStatus.Unconditional), Count(SaleStatus.Settled), Count(SaleStatus.Withdrawn),
            ListValue: list.Where(u => u.Status != SaleStatus.Withdrawn).Sum(u => u.Fields.ListPrice?.Amount ?? 0m),
            ContractedValue: list.Where(u => SaleRules.IsContracted(u.Status)).Sum(u => u.Sale?.SalePrice?.Amount ?? 0m),
            SettledValue: list.Where(u => u.Status == SaleStatus.Settled).Sum(u => u.Sale?.SalePrice?.Amount ?? 0m));
    }
}
```

`Features/SaleValidators.cs` — `UpdateSaleValidator : AbstractValidator<UpdateSaleRequest>`:

  - BuyerName: `NotEmpty().WithMessage("Enter the buyer's name.")` (every sale status), ≤ 200.
  - BuyerEmail: `.EmailAddress().When(not blank)`, ≤ 200. BuyerPhone ≤ 50. BuyerSolicitor ≤ 200.

  - DepositAmount: `≥ 0`; `PrecisionScale(18, 2, true)`; `Must((x, d) => d is null || x.SalePriceAmount is null || d <= x.SalePriceAmount).WithMessage("Deposit can't be more than the sale price.")`.

  - SettlementDate: `NotNull().WithMessage("Enter the settlement date.").When(RequiresSettlement)`; `Must((x, d) => SaleRules.IsOrdered(x.AgreementDate, d) && SaleRules.IsOrdered(x.UnconditionalDate, d)).WithMessage("Settlement date must be on or after the agreement and unconditional dates.")`.

The validator must cover every rule `SaleRules.EnsureValid` throws on, so a valid request never reaches a domain exception (Review Focus 1).
