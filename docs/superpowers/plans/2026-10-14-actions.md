# Actions, People and Home: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let people answer "what do I need to do today?". This plan adds per-project actions with real owners from a people directory, and a Home dashboard that becomes the landing page.

**Architecture:** There's a host-level people directory: the interface is in `PDS.Shared`, and the Cognito or configured implementation is in `PDS.Api`. The new `PDS.Actions` module owns the `actions` table, which has two sparse GSIs (owner and open-by-due). There's an additive `GET /api/risks/high` in Risks. On the web, `features/actions` has a section for the project page, and `features/home` has a panel-based dashboard at `/`.

**Tech Stack:** .NET 10 Minimal APIs, DynamoDB, AWS SDK v4 (adding `AWSSDK.CognitoIdentityProvider`), FluentValidation, React 19 with Mantine 9 and TanStack Query, and CDK (C#).

**Spec:** `docs/superpowers/specs/2026-10-14-actions-design.md`

## Global Constraints

- **Foundation constraints:**
  - net10.0 with central package versions (`Directory.Packages.props`).
  - In modules, only `Contracts/*` and the `*Module` class are public.
  - Keys are `pk`/`sk`/`gsi1pk`/`gsi1sk`/`gsi2pk`/`gsi2sk` strings.
  - Errors are ProblemDetails. JSON is camelCase with string enums.
- **Module rule:** `PDS.Actions` references only `PDS.Shared` and `PDS.Portfolio` (Contracts types only).
- **No new tests** (user directive). Verify with:
  - `dotnet format PDS.slnx`, then `dotnet build PDS.slnx` (0 warnings).
  - In `web/`: `npm run gen:api && npm run typecheck && npm run lint && npm run build`.
  - In `infra/`: `npx aws-cdk@2.1143.0 synth -c deployment=example-dev` (or `dotnet run --project PDS.Infra -- ` via cdk.json).
  - The manual checks each task names.
- API on `--urls http://localhost:5094`, Vite on `--port 5204`. DynamoDB Local is shared on :8000: never stop it.
- **Today** is `LocalDate.Today(clock, locale.Value)` (`PDS.Shared.Settings`). Overdue means the action is open, has a due date, and `dueDate < today`.
- Open means status ∈ {Open, InProgress}. Closed means status ∈ {Done, Cancelled}.
- **Policies:**
  - Reads need CanRead.
  - Create, update and cancel need CanWrite.
  - Complete and reopen need CanRead plus (CanWrite role or `user.Id == action.OwnerId`); otherwise 403.
- **Archived project:** create, update and cancel return 400 on `projectId`. Complete and reopen are allowed. `/mine` and `/overdue` exclude archived projects.
- **Shared-file edits** are minimal and additive (`PDS.slnx`, `Program.cs`, `PDS.Api.csproj`, `infra/PDS.Infra/Program.cs`, `PDS.Infra.csproj`, `routes.tsx`, `AppLayout.tsx` nav, and `ProjectDetailPage.tsx`, which gets exactly one render line plus its import).
- Commit messages are `feat(<area>): …` and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Viewer owner vs non-owner.**
   - A Viewer who owns an action can `POST …/complete` and `…/reopen` (200).
   - The same call by a Viewer who isn't the owner returns 403, never 200, and never changes the action.
   - A Viewer's create, update or cancel returns 403 (from the policy).
2. **Owner left the directory.**
   - PUT with an unchanged `ownerId` that's no longer in `/api/people` succeeds and keeps `ownerName`.
   - PUT or POST with a new unknown `ownerId` returns 400 on `ownerId`.
3. **GSI hygiene.**
   - Completing or cancelling an action removes it from `/mine` and `/overdue`. Reopening puts it back.
   - Clearing the due date removes it from `/overdue`.
   - Changing the owner moves it between users' `/mine`.
   - Because items are written with a full Put, absent gsi attributes must truly be absent, not empty strings.
4. **Overdue boundary in NZ time.** Due = today is not overdue. Due = yesterday is overdue. No due date is never overdue.
5. **A Home page with one failing API.** If `/api/risks/high` or `/api/consents/due` errors, that panel shows an inline alert and every other panel still renders.

`ConfiguredPeopleDirectory(IOptions<PeopleOptions>, IOptions<AuthOptions>)`:
- Maps `Users` to `Person`.
- If the dev user's id isn't in the list, it appends `Auth:DevUser`, taking the role as the highest of `DevUser.Roles` with a Viewer fallback.
- Sorts by name, with `FindAsync` matching on an ordinal id comparison.

- [ ] **Step 3: Cognito source.** `CognitoPeopleDirectory(IAmazonCognitoIdentityProvider cognito, IOptions<PeopleOptions> options)`:
- For each role in `[Roles.Admin, Roles.Manager, Roles.Viewer]` (the highest first), page through `ListUsersInGroupAsync(new ListUsersInGroupRequest { UserPoolId, GroupName = role, Limit = 60, NextToken })`.
- For each `UserType` with `Enabled == true`, read the attributes `sub` (skip the user if it's missing), `name` and `email`.
- Name = `name` ?? `email` ?? `Username`.
- The first role seen for a sub wins, because the groups are iterated highest first.
- Return the result sorted by name.
- Register the client lazily, like the SNS client in `ConsentsModule`: `try { new AmazonCognitoIdentityProviderClient() } catch (AmazonClientException) { new AmazonCognitoIdentityProviderClient(RegionEndpoint.APSoutheast2) }`.

- [ ] **Step 4: Cache.** `CachedPeopleDirectory(IPeopleDirectory inner, TimeProvider clock)` is a singleton decorator.
- It holds `(IReadOnlyList<Person> People, DateTimeOffset LoadedAt)?` with a `SemaphoreSlim(1,1)` and a TTL of `TimeSpan.FromMinutes(5)`.
- `FindAsync` reads from the cached list.
- On an inner exception the cache isn't replaced, and the exception propagates.

- [ ] **Step 5: DI plus endpoint.**

- [ ] **Step 2: Table plus mapper plus store.**
`ActionsTable.Definition = new(LogicalName, [new GlobalIndex(Gsi1, "gsi1pk", "gsi1sk"), new GlobalIndex(Gsi2, "gsi2pk", "gsi2sk")])`.

`ActionItemMapper.ToItem` follows the `RiskItemMapper` layout: `pk=PROJECT#<pid>`, `sk=ACTION#<aid>`, attributes `id, projectId, title, description?, ownerId, ownerName, dueDate?, priority, status, link (M: module, recordId, label)?, completedAt/completedBy?, created*/updated*, version`. In addition, **only when `IsOpen`**:
```csharp
item["gsi1pk"] = Attr.S($"OWNER#{f.OwnerId}");
item["gsi1sk"] = Attr.S($"{(f.DueDate is { } d ? d.ToString("yyyy-MM-dd", CultureInfo.InvariantCulture) : ActionRules.NoDueSortKey)}#{a.Id.Value}");
if (f.DueDate is { } due) { item["gsi2pk"] = Attr.S("OPEN"); item["gsi2sk"] = Attr.S($"{due:yyyy-MM-dd}#{a.Id.Value}"); }
```
Use invariant formatting. Because the store always writes with a full `PutItem`, closing an action naturally removes these attributes.

`ActionStore`:
- `GetAsync`, `ListForProjectAsync`, `CreateAsync` and `UpdateAsync` work exactly like `RiskStore`.
- `ListOpenForOwnerAsync(ownerId)` is a paged `QueryAsync` on `IndexName = gsi1` with `gsi1pk = :pk`.
- `ListOverdueAsync(today)` is a paged query on `gsi2` with `gsi2pk = :open AND gsi2sk < :today`, where `:today = "yyyy-MM-dd"`. Lexical order works because `#` follows the date: `2026-10-18#…` > `2026-10-18`, so today is not overdue.
- GSI reads can't be `ConsistentRead`, so omit it.

- [ ] **Step 4: Owner resolution.** `OwnerResolver.ResolveAsync(IPeopleDirectory people, string ownerId, ActionFields? existing, CancellationToken ct) → Task<(string Id, string Name)?>`:
- If `existing` is set and `existing.OwnerId == ownerId`, return the stored `(OwnerId, OwnerName)`. Don't look it up, so a departed owner keeps working.

- [ ] **Step 5: Endpoints.**
- **List:** returns 404 for an unknown project; filters `includeClosed`; and sorts open first, then overdue, then `DueDate ?? DateOnly.MaxValue`, then priority descending, then title (OrdinalIgnoreCase). Closed actions sort `Completed.At` descending. Each item is `ActionDetails.From(a, today)`.
- **Get:** 404 when missing.
- **Create:** CanWrite. Returns 404 for an unknown project, and 400 for an archived project or an unknown owner. Priority defaults to `Normal`. Returns `Created($"/api/actions/projects/{pid}/actions/{id}", dto)`.
- **Update:** CanWrite. Returns 404 when missing. Then checks, in order: 409 on a version mismatch, 400 if closed, 400 if the project is archived (`ProjectLookup`), and 400 for an unknown owner. Then it calls `Update` and stores the action, returning 409 if the store reports a conflict.
- **ChangeActionStatus:** maps three routes with a shared `Change(...)` helper, mirroring `CloseRisk.Change`. Its steps:
  1. Load the action (404 if missing).
  2. **Authorise:** `allowOwner && user.Id == action.Fields.OwnerId` or `user.Roles` contains Manager or Admin. Otherwise return `NotOwner()` (403).
  3. If it's a no-op, return 200 with the current state.
  4. Return 409 on a version mismatch.
  5. For cancel only, return 400 if the project is archived.
  6. Apply the change and store it.

  The routes are complete (`allowOwner: true`, CanRead), reopen (`allowOwner: true`, CanRead) and cancel (CanWrite policy, `allowOwner: false`).

`ActionsModule.MapActionsEndpoints` maps the group with `.WithTags("Actions").RequireAuthorization(Policies.CanRead)`. `AddActionsModule` registers `ActionsTable.Definition`, `ActionStore` and the validators (`includeInternalTypes: true`).
